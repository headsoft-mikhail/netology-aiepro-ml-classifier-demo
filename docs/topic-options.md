## Рекомендация

Выбрать основную траекторию **ML/DL** и небольшую задачу классификации, где самостоятельно обучается MLP. Это прямо связано с изученным материалом и даёт практику forward/backward, loss, оптимизатора, learning rate, batch size, регуляризации и проверки обобщения. RAG оставить резервным вариантом для быстрой сдачи.

Приоритет — качественный датасет и понятный эксперимент, а не большая система. Для собственного проекта требуется согласование с экспертом. Не выбирать тему окончательно до небольшой проверки данных и возможности улучшить baseline.

## Примеры по направлениям

| Вариант | Бизнес-сценарий и результат | Что обучать/улучшать | Чем подтвердить |
|---|---|---|---|
| ML/DL: классификатор обращений на качественных данных | Сервис поддержки направляет текст в очередь «доставка», «оплата», «возврат» и т. п.; неуверенные запросы передаёт оператору | TF-IDF + линейная модель как ориентир; базовый MLP → улучшенный MLP; при желании другой способ представления текста | Accuracy, precision, recall, macro/weighted F1, confusion matrix; отдельно доля автоматизации и ошибки среди автоматически принятых решений |
| ML/DL: контроль качества партии по измерениям | Оператор получает класс «годно/проверить» по числовым характеристикам изделия; уменьшает пропуск брака | Маленький MLP с нуля, сравнение с логистической регрессией/деревьями; нормализация, размер сети, веса классов, регуляризация | Обязательные классификационные метрики плюс recall брака и число ложных тревог; порог выбирается на validation |
| ML/DL: определение категории товара по изображению | Контент-менеджер магазина получает предложенную категорию при загрузке карточки | MLP по уменьшенным изображениям как учебная основа, затем небольшая CNN как самостоятельное расширение | Классификационные метрики, ошибки по категориям, одинаковый test; требуется согласовать тему и самостоятельно изучить CNN |
| LLM: заявка из свободного текста в JSON | Сотрудник сервисного центра вводит описание проблемы; система извлекает устройство, симптом, срочность и недостающие сведения | Системный prompt/few-shot, схема ответа, проверка и контролируемый retry; fine-tuning только как дополнительный этап по согласованию | ≥10 запросов; точность полей, валидность JSON, задержка; правдоподобный, но неверный JSON не считать успехом |
| RAG: помощник по гарантийным правилам | Оператор отвечает по актуальным правилам с источником и отказывается выдумывать отсутствующие условия | Использовать текущий RAG; улучшить полноту составных ответов, поиск или prompt | ≥10 вопросов трёх обязательных типов; источники, корректность, полнота, отказы; текущий README содержит только 9 вопросов |
| ИИ-агенты: развитие консультанта по сетевому оборудованию | Покупатель получает подбор совместимых устройств и передачу оператору при нерешённой проблеме | Добавить содержательно новый инструмент проверки совместимости либо маршрутизацию/эскалацию; сохранить RAG и память | ≥8 сценариев до/после, включая tools/RAG/memory, неизвестное и отказ компонента; одних уже имеющихся тестов недостаточно для доказательства нового улучшения |

Для нейросетей я бы выбрал первые два варианта. Первый ближе к исходной теме курса и вашему опыту; второй меньше отвлекает на обработку языка и нагляднее показывает влияние масштабирования признаков и параметров обучения. Третий интересен визуально, но требует дополнительных знаний. LLM/агенты тренируют прежде всего инженерную работу вокруг готовой модели; собственно обучение сети там легко снова отодвинуть на второй план.

## Данные: до утверждения темы

Конкретные внешние датасеты пока не выбраны и не проверены. Нужны доступная лицензия, понятные классы, достаточные независимые примеры и разумный размер. Предпочтителен готовый размеченный набор, чтобы диплом не превратился в проект сбора данных.

В тексте не переносить шаблоны, перефразировки и дубликаты между train/validation/test. Для измерений и изображений учитывать партии, устройства или исходные объекты: связанные записи не должны давать утечку. При необходимости группового разбиения согласовать его вместе с требованием stratify.

Нельзя сравнивать старую модель на плохом старом наборе с новой на другом качественном наборе и называть это улучшением. При смене данных заново обучить и зафиксировать baseline на новом train, после чего сравнивать все версии на одном test.

## Минимальный объём ML/DL-диплома

1. Одна классификационная бизнес-задача, один набор данных, один основной endpoint `/predict` и `GET /health`.
2. Зафиксировать разбиение и baseline, записать критерии и целевые значения до оптимизации.
3. Небольшой MLP и несколько осмысленных экспериментов: learning rate; размер сети; регуляризация/early stopping. Менять факторы последовательно и объяснять результат.
4. MLflow, кривые train/validation loss, полный обязательный набор test-метрик, анализ ошибок. Не подбирать параметры на test.
5. Сохранённые модель и preprocessing; сервис загружает их без обучения.
6. FastAPI, конфигурация, безопасные ошибки, логирование, тесты, три общих контрольных сценария.
7. Docker, проверка в чистом окружении, короткое видео, README, таблица требований, презентация 7–10 слайдов, портфолио.

Окончательные численные пороги ставить после первичного baseline, до серии доработок. Не обещать заранее произвольные 95% accuracy. Для зачёта требуется реальное улучшение минимум одного согласованного критерия без критического ухудшения остальных; если нейросеть не превосходит классический алгоритм, это честно отразить и объяснить.

## Конкретные наборы и сценарии

Источники проверены 1 октября 2026. Пока выполнена проверка описаний/происхождения, а не скачивание, аудит строк или обучение. Реальность данных не гарантирует улучшение любой выбранной модели. Размеры — по карточкам первоисточников; дубликаты, доли классов и утечки требуется проверить перед baseline.

### 1. Dry Bean — основной кандидат для понимания MLP

[UCI, первоисточник](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset). 13 611 реальных зёрен, 16 числовых признаков, 7 сортов. Признаки извлечены из фотографий: площадь, периметр, оси, характеристики формы. В проект подаётся готовая таблица; фото и извлечение признаков находятся за границами сервиса.

**Сценарий:** модуль сортировочной линии принимает измерения зерна и возвращает сорт. **MLP:** например, 16 → 64 → 32 → 7 (3399 параметров), CrossEntropyLoss. Достаточно нескольких тысяч весов, а не большой сети.

Плюсы: мало возни с preprocessing, многоклассовая задача, понятные признаки, сравнительно много наблюдений. Можно исследовать нормализацию, learning rate, размер сети и weight decay. Ограничения: сорта могут быть похожи по форме; это проверка в условиях исходного исследования, а не доказательство переноса на любую камеру/партию. Проверить дубликаты до разбиения. Это мой первый выбор по соотношению учебной пользы и объёма.

### 2. Банковские просрочки — если интереснее бизнес

[UCI Default of Credit Card Clients](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients). 30 000 записей, 23 признака, реальные исторические данные Тайваня: лимит, счета, суммы и история платежей; бинарная метка default.

**Сценарий:** учебный сервис риск-аналитика оценивает вероятность просрочки следующего платежа. Небольшой MLP; полезно изучать дисбаланс, масштабирование сумм, веса классов и порог. ID исключить, категориальные коды не трактовать автоматически как непрерывные числа. Исторические данные не представлять как современную универсальную банковскую модель. Предположение: потребует больше подготовки данных, чем Dry Bean. Не обещать нейросети победу над бустингом.

### 3. Cardiotocography — медицинская альтернатива

[UCI Cardiotocography](https://archive.ics.uci.edu/dataset/193/cardiotocography). 2126 кардиотокограмм, 21 измеренный признак; разметка по согласию трёх акушеров. Выбрать трёхклассовую цель NSP: normal/suspect/pathologic.

**Сценарий:** учебный прототип приоритизации записей для просмотра специалистом. MLP по готовым измерениям, не по сырому сигналу. Полезны дисбаланс, recall редкого класса, анализ ошибок. Меньше наблюдений — больше разброс оценки. **CLASS (другая экспертная разметка) не включать во входные признаки для предсказания NSP.** Ограничить заявление о пользе учебной оценкой на исходном наборе, не клинической валидацией.

### 4. Steel Plates Faults — промышленная альтернатива

[UCI Steel Plates Faults](https://archive.ics.uci.edu/dataset/198/steel+plates+faults). 1941 наблюдение, 27 признаков, 7 типов дефекта; исходный опубликованный набор, а не синтетическая версия соревнований Kaggle.

**Сценарий:** по измеренным характеристикам уже обнаруженного дефекта определить его тип для контроля качества. Важное отличие: в наборе нет класса «годно», поэтому обещать обнаружение любого брака среди годных изделий нельзя. Нужны разбор технических признаков и оценка малых классов. Менее удобен для первого спокойного эксперимента, чем Dry Bean.

### 5. BANKING77 — если хочется именно обращения

[Репозиторий авторов](https://github.com/PolyAI-LDN/task-specific-datasets), [статья](https://arxiv.org/html/2003.04807). 13 083 англоязычных запроса, 77 намерений, готовые train/test 10 003/3080. Примеры: карта не пришла, не проходит перевод, карта не работает.

**Сценарий:** маршрутизация обращения банковской поддержки по категории. TF-IDF + LinearSVC как ориентир; MLP по TF-IDF либо фиксированным embeddings. Можно выбрать заранее обоснованный набор 10–15 категорий, но явно указать ограниченный охват и не называть это результатом на полном BANKING77.

Авторы описывают размеченные customer-service queries, однако просмотренные README/статья не дают достаточно подробного происхождения каждой реплики, чтобы гарантировать, что весь набор — неизменённые выгрузки реальных клиентских чатов. При строгом требовании именно такой природы текстов нужна дополнительная проверка происхождения либо другой источник. Поэтому он не первый выбор по критерию уверенности в реальных наблюдениях. Текстовая предобработка и схожесть 77 намерений также отвлекают от чистого изучения MLP.

## Как уложиться в небольшой учебный проект

Выбрать один набор. Сделать простую классическую модель-ориентир и честный базовый MLP с нормальными настройками. Затем 4–6 осмысленных экспериментов, меняя по одному фактору: learning rate, ширину/глубину, регуляризацию. Не портить baseline специально ради красивого улучшения. Для выбранных baseline/final полезно проверить несколько seed, чтобы отличить эффект от случайности.

Для каждого опыта заранее записывать ожидание, затем train/validation loss и macro-F1, затем объяснение результата. Дипломный test оставить для заключительной оценки двух зафиксированных версий. Изменение порога само по себе не заменяет понимание обучения; основной учебный вклад — работа с сетью.

Сервис: `/predict` + `/health`, сохранённые preprocessing и веса, конфиг, обработка плохого ввода/недоступного артефакта, логи, несколько pytest-тестов, Docker, короткая демонстрация. MLflow локальный. Без фронтенда, авторизации, Kubernetes, очередей, отдельных БД и большого мониторинга. Презентация и требования остаются обязательными.

Для нового предметного сценария согласовать траекторию ML/DL с экспертом: сохраняются все классификационные метрики, train/validation/test, MLflow, артефакт модели и сравнение до/после. Для улучшения выбрать гиперпараметры/работу с дисбалансом — они прямо перечислены в задании.

## Оборудование и изоляция

Для табличных наборов этого размера и MLP из нескольких тысяч весов разумно начать с CPU на Mac M1 16 ГБ. Это оценка масштаба задачи, не замер времени. RTX 5080 пока не нужна; ускоритель у такой маленькой сети может тратить заметную долю времени на накладные расходы.

На Mac можно обучать в окружении проекта; при желании полностью контейнеризировать — CPU-контейнер. Обычный Linux-контейнер не следует планировать как способ доступа PyTorch к Apple MPS. Docker обязателен для финального воспроизводимого сервиса независимо от места обучения.

Если позднее потребуется NVIDIA: разработка на Mac, обучение в Linux-контейнере на Windows, передача только данных/конфига и возврат весов/отчётов. На Windows нужны совместимый драйвер NVIDIA, WSL2 и Docker Desktop с WSL2 backend; Python, PyTorch и CUDA runtime проекта живут внутри образа. Это не ноль изменений хоста: драйвер, WSL, Docker и место под образы остаются. Поддержку RTX 5080 конкретным образом PyTorch/CUDA проверить перед установкой; образ в этой задаче не выбирался и не запускался. [Требования Docker](https://docs.docker.com/desktop/features/gpu/).

Образы для Mac arm64 и Windows/WSL x86_64 могут различаться; обмениваться лучше исходниками и весами, а не одним бинарным окружением. Никаких установок или изменений на ПК не выполнялось.

## MLP или CNN

MLP соединяет признаки полносвязными слоями — подходит готовым числовым измерениям. CNN использует локальность и общие фильтры изображения, а не просто является «более мощной MLP». Маленькие изображения не обязательно требуют большой сети или мощного ПК. Но сейчас CNN добавит новую архитектуру и обработку изображений без необходимости для вашей цели; разумнее сначала разобраться с MLP.

**Текущий выбор:** Dry Bean — наиболее простой путь к пониманию обучения; банковские просрочки — если больше привлекает бизнес-смысл; Cardiotocography — если интересна медицина. Тема ещё не утверждена, эксперту ничего не отправлено.

### Бизнес-кейс

Предполагаемый заказчик — диагностическое подразделение клиники; пользователь — специалист, просматривающий исследования. Проблема: поступающие записи требуют ручного просмотра, и полезно заранее выделить записи, которые модель относит к подозрительным или патологическим. После получения уже рассчитанных 21 числового признака сервис предлагает один из трёх классов и оценки модели по классам. Врач получает подсказку для очередности просмотра; ни одна запись автоматически не исключается из рассмотрения.

Ожидаемая бизнес-польза — помощь в выделении требующих внимания записей. Она является гипотезой: набор не содержит данных рабочего процесса или времени врача, поэтому нельзя заявить доказанное сокращение времени, улучшение исходов либо конкретный процент экономии. Проверяем только согласие модели с экспертными метками, характер ошибок и задержку сервиса. Прототип не выдаёт диагноз, назначение лечения или клиническую рекомендацию.

### Данные и границы

[UCI Cardiotocography](https://archive.ics.uci.edu/dataset/193/cardiotocography), DOI 10.24432/C51S4N, CC BY 4.0 с указанием авторов. 2126 реальных записей КТГ, 21 признак; три акушера сформировали согласованную разметку. Целевая переменная NSP: normal/suspect/pathologic. Использовать признаки, обозначенные UCI как features; исключить альтернативную экспертную метку CLASS, NSP из входов и служебные поля исходного XLS.

На входе не фотография графика, не PDF и не сырой временной ряд. Извлечение признаков из аппаратуры не входит в учебный проект. Сервис демонстрируется на строках открытого набора. Исходные файлы ещё не скачаны: перед обучением нужны проверка структуры, частот классов, дубликатов и наличия идентификаторов пациентов/групп. Если идентификаторов нет, независимость пациентов подтвердить нельзя; ограничение явно описать. Совпадающие измерения не должны разойтись между выборками.

### Mac и модель

Небольшой MLP, например 21 → 32 → 16 → 3: 1283 параметра. Начать с CPU на Mac M1 16 ГБ; RTX/Windows не требуются по масштабу задачи. Время пока не измерено. Зависимости в окружении проекта, финальный сервис в CPU Docker. Не добавлять CNN, RNN или LLM.

Baseline — разумно настроенный MLP с нормализацией; логистическая регрессия — дополнительный ориентир. Доработка: подбор learning rate и размера сети, затем регуляризация/веса классов по результатам validation. Это прямо соответствует разрешённым направлениям «гиперпараметры» и «дисбаланс». 4–6 осмысленных экспериментов, не массовый поиск.

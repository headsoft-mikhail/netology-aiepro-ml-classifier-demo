## 1. ml-pipeline

**Просмотрено:** README, `coffee_ml_pipeline.ipynb`, `coffee_ml_pipeline_dag.py`.

Классификация вида напитка по времени покупки и календарным признакам. 3547 записей, 8 классов. EDA, feature engineering, ColumnTransformer, StandardScaler, OneHotEncoder, DummyClassifier, LogisticRegression, RandomForest, GradientBoosting, стратифицированная кросс-валидация, Optuna (100 trials), MLflow. Написан еженедельный DAG Airflow из трёх стадий; его фактический запуск не проверен.

В сохранённой итоговой таблице RandomForest после Optuna: test accuracy 0,290, macro-F1 0,251; до настройки — 0,273 и 0,238. Нейросетей нет. Хотя исходное задание упоминает сумму чека, в фактический ColumnTransformer включены только календарные и временные признаки.

**Для диплома:** готовый опыт воспроизводимых ML-экспериментов. Прогноз спроса кофейни был бы другой задачей — регрессией количества продаж, а не угадыванием названия напитка.

## 2. netology-aiml-classification

**Просмотрено:** README, код моделей и сохранённые результаты `notebook.ipynb`.

Классификация обращений поддержки на 5 классов. Очистка текста, TF-IDF, LogisticRegression, LinearSVC, RandomForest; дополнительный эксперимент с категориальными и числовыми признаками; PyTorch MLP: 256 → 128 → 5, ReLU, Dropout 0,3, Adam, CrossEntropyLoss, 20 эпох. Есть MLflow, classification report, confusion matrix и кривые loss.

Macro-F1 на тесте: LogisticRegression 0,2111; LinearSVC 0,2095; RandomForest 0,2066; MLP 0,2067. У MLP train accuracy около 0,95 при test accuracy около 0,21; test loss растёт примерно с 1,61 до 3,90. Это показывает переобучение. Автор предполагает слабую связь текстов с метками; по одному обзору эту причину нельзя считать доказанной.

**Для диплома:** базовый цикл обучения нейросети уже реализован; в этом конкретном проекте успешного обобщения не видно. Добавленный позднее Colab по Breast Cancer показывает более успешный опыт (см. ниже). Имеет смысл взять новую качественно размеченную задачу и системно сравнить learning rate, размер сети, регуляризацию и раннюю остановку. Нужны отдельные train/validation/test: здесь test loss вычислялся каждую эпоху, а в новом проекте тест следует оставить для финального замера.

## 3. netology-airag-rag-pipeline

**Просмотрено:** README и структура файлов.

Полный RAG pipeline: TXT/JSON/HTML → очистка и Unicode-нормализация → точная и MinHash-дедупликация → чанкинг с overlap → embeddings → Qdrant → retrieval → LLM. Конфигурация YAML, manifests и происхождение фрагментов, сравнение baseline и улучшений.

Учебная база: 15 исходных документов, 13 после дедупликации. Evaluation включает 9 вопросов разных типов. В README честно отмечены неполные ответы на составные вопросы, хотя retrieval находит нужные источники.

**Для диплома:** значительная готовая основа RAG. Однако готовность «на 95%» нельзя подтвердить до сверки с требованиями диплома. Для изучения обучения нейросетей повтор такого проекта даст мало нового.

## 4. netology-aiagnt

**Просмотрено:** README и структура исходников/тестов.

Консультант по сетевому оборудованию: LLM-планировщик, RAG, SQLite-каталог из 35 устройств пяти категорий, два поисковых инструмента, краткосрочная и долговременная память, типизированные ответы, trace, FastAPI, Docker и обработка ошибок.

README сообщает о 66 пройденных тестах и покрытии 84%; это не проверялось повторным запуском. Сценарные тесты используют детерминированный подставной LLM-клиент: они подтверждают логику оркестрации, но не измеряют реальное качество живой модели.

**Для диплома:** сильная основа инженерного LLM/агентного проекта и возможный интерфейс к будущей модели. Не стоит автоматически включать всю эту инфраструктуру в новый диплом: она может отвлечь от обучения нейросетей.

## 5. netology-dataset-fine-tuning

**Просмотрено:** README и состав файлов.

Подготовка учебного датасета: очистка 22 исходных записей до 11, генерация двух перефразировок на вопрос через Groq, 33 диалога в JSONL с system/user/assistant. Валидация, дедупликация, повтор запросов и 8 тестов, согласно README.

**Для диплома:** опыт очистки и формата данных уже есть. Масштаб маленький; перефразировки нельзя разносить между train и test, иначе оценка будет измерять знакомство с исходными примерами.

## 6. netology-aiagnt-finetuning

**Просмотрено:** README, начало `fine_tuning/train.py` (токенизация, маскирование labels, collator, загрузка и evaluation).

Qwen2.5-0.5B-Instruct + LoRA на q_proj/v_proj (rank 8), локально на Mac/MPS с 16 GiB памяти. 32 train-примера, 5 eval-примеров, 2 эпохи, 16 шагов. Loss считается только по ответу assistant; есть baseline, адаптер и сравнение генераций.

Сохранённые результаты: eval loss 1,7137 → 1,4528; perplexity 5,5495 → 4,2752; ручная проверка — 0/5 и до, и после. Снижение teacher-forced loss не стало прикладным улучшением. Причины из README — гипотезы; пять примеров недостаточны для надёжной оценки.

**Для диплома:** можно продолжить fine-tuning, но это будет повтор знакомого направления с большим упором на данные и оценку. Для понимания базовых механизмов нейросетей маленькая модель, обученная с нуля, может быть нагляднее.

## Вывод для выбора

Есть опыт ML-pipeline, сравнения алгоритмов, PyTorch MLP, RAG, агентов и LoRA. Наиболее полезный следующий шаг — небольшой эксперимент, где понятны входы, метки, функция потерь и бизнес-ошибка; обучение быстро повторяется и можно объяснить изменение качества.

После чтения программы и задания: самый прямой путь — классификация текста либо табличных объектов с MLP и сильным классическим ориентиром. CNN и обучаемые текстовые embeddings — расширение относительно явно названного блока PyTorch/MLP. Регрессия требует согласования метрик, поскольку условия ML/DL прямо перечисляют классификационные метрики и stratify. Подробности — в `topic-options.md` и `course-outline.md`.

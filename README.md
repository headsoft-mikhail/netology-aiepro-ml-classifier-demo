# CTG classifier demo

Учебный дипломный проект по траектории ML/DL: сервис классификации результатов кардиотокографии (КТГ). Модели определяют морфологический паттерн **CLASS** и категорию состояния **NSP** по 21 измерению. Исследованы классические классификаторы и MLP; для сервиса выбраны две независимые оптимизированные RandomForest.

## Задача и сценарий

Пользователь — специалист, просматривающий поступившие исследования. Сервис помогает выделять подозрительные и патологические результаты для более ранней ручной проверки. Важнее не пропустить такие записи, хотя ложные предупреждения тоже увеличивают нагрузку.

В демо пользователь отправляет один из 20 фиксированных контрольных примеров. Сервис получает измерения, предсказывает CLASS и NSP, сохраняет результат в SQLite и отображает его в таблице. Патологические записи располагаются первыми, затем подозрительные и нормальные. Истинные метки известны для сравнения и не передаются моделям.

Это учебная демонстрация на историческом датасете, без клинической проверки. Метка модели используется для демонстрационной приоритизации; она не является диагнозом или решением о лечении. Реального подключения к медицинской системе нет.

## Данные и исследования

Источник — [UCI Cardiotocography](https://archive.ics.uci.edu/dataset/193/cardiotocography), Campos & Bernardes (2000), DOI 10.24432/C51S4N, лицензия CC BY 4.0. Это реальные измерения, не синтетические данные. Используется исходный лист **Raw Data** файла CTG.xls.

CLASS содержит 10 паттернов, NSP — Normal, Suspect и Pathologic. Обе колонки — целевые; их и индикаторы паттернов исключаем из входа. CLASS не преобразуется автоматически в NSP: обучаются два отдельных классификатора. После очистки остаётся 2108 записей. Разбиение примерно 60/20/20: **1266 train, 421 validation, 421 test**, seed 42. StratifiedGroupKFold учитывает CLASS и FileName, поэтому сегменты одного исходного исследования не попадают в разные части.

Входы: `LB, AC, FM, UC, ASTV, MSTV, ALTV, MLTV, DL, DS, DP, Min, Max, Nmax, Nzeros, Mode, Mean, Median, Variance, Tendency, duration`. duration вычисляется как e − b; идентификаторы и исключённые измерения удаляются при подготовке. StandardScaler обучается только на train внутри sklearn Pipeline.

Исследование описано в [experiments/README.md](experiments/README.md):

| Блокнот | Содержание |
|---|---|
| [01_eda](experiments/01_eda.ipynb) | Загрузка, словарь исходных колонок, очистка, первичные выводы |
| [02_preparation](experiments/02_preparation.ipynb) | Разбиение, связь целей, распределения, корреляции, выбор признаков |
| [03_classical_models](experiments/03_classical_models.ipynb) | DummyClassifier, LogisticRegression, LinearSVC, RandomForest; Optuna и итоговая оценка |
| [04_neural_models](experiments/04_neural_models.ipynb) | Обучение MLP, подбор, сравнение с классическими моделями, ограничения |

Рабочий baseline — исходный RandomForest для каждой цели. Optuna настраивает три классических семейства: 25 попыток на семейство и цель, затем 50 попыток для уточнения выбранного семейства. Выбор производится по validation; test используется для итогового сравнения. MLP остаётся исследовательским сравнением, в API она не используется.

## Результаты до/после

Последний отчёт Airflow-пайплайна: `runtime/reports/trained_classifier_comparison_metrics.csv`. Все строки ниже относятся к **одним и тем же 421 записям test**.

| Цель / вариант | Accuracy | Macro-precision | Macro-recall | Macro-F1 | Weighted-F1 |
|---|---:|---:|---:|---:|---:|
| CLASS baseline | 0,808 | 0,859 | 0,674 | 0,710 | 0,796 |
| CLASS выбранный | 0,822 | 0,777 | 0,792 | 0,779 | 0,823 |
| NSP baseline | 0,910 | 0,846 | 0,826 | 0,833 | 0,912 |
| NSP выбранный | 0,895 | 0,805 | 0,850 | 0,820 | 0,902 |

Для CLASS macro-F1 вырос, но macro-precision снизился. Для NSP общие F1 и accuracy не улучшились. В исследовательском сравнении ошибки Pathologic → Normal сократились с 1 до 0, Suspect → Normal — с 13 до 8; ложные предупреждения Normal → Suspect/Pathologic выросли с 17 до 28. Выбранный вариант NSP отражает приоритет обнаружения предупреждений, а не улучшение всех метрик.

Macro-F1 одинаково учитывает категории. Weighted-F1 сильнее зависит от частых классов и служит дополнительной метрикой: он не должен скрывать пропуски редких патологических результатов. Матрицы ошибок и метрики отдельных классов сохранены в блокнотах и MLflow.

В блокнотах на macOS записаны немного другие результаты CLASS (0,712 → 0,777), чем в Linux-пайплайне. При одинаковых данных и параметрах выбранный лес отличается тремя деревьями и одним ответом на test: паттерн SUSP вместо A для истинного SUSP. Повторное обучение на Mac воспроизводит все 100 деревьев блокнота, а в Linux — все 100 деревьев пайплайна при одинаковых версиях библиотек. Причина — разные машинные инструкции вычисления Gini-критерия: слитные операции на macOS и раздельные на Linux разрешают равные по точному качеству разбиения по-разному. Подробности: [воспроизводимость](docs/reproducibility.md). Эти результаты относятся к разным средам выполнения и не смешиваются. Test уже просматривался при обсуждении итогового выбора, поэтому не считаем его полностью новой независимой проверкой и не продолжаем настройку по нему.

## Архитектура

```text
UCI ZIP → Airflow: скачать → подготовить → обучить RandomForest
                                      ↓
                           модели + отчёт + MLflow
                                      ↓
контрольный CSV → FastAPI / modern_di → предсказания → SQLite
                       ↓
                HTML / CSS / JavaScript
```

- `src/classifier/pipeline/`: DAG, загрузка, подготовка, обучение, схема данных и настройки.
- `src/classifier/api/`: FastAPI, модели HTTP-контракта, зависимости, ресурсы, repositories и use case отправки.
- `src/classifier/frontend/`: страница без отдельной сборки, раздаётся FastAPI.
- `experiments/`: четыре блокнота и настройки экспериментов.
- `tests/`: тесты подготовки, предсказания, API и отчёты проверок.

Модели и контрольный CSV загружаются в lifespan один раз. AppCache и PredictionsRepository имеют APP scope; SQLite-соединение, AnalysisRepository и SubmitDemoRecordUseCase — REQUEST scope. DI закрывает соединение после запроса. API использует готовые модели, доступ к MLflow при его работе не требуется.

## Установка и запуск

Нужны Python **3.14.7**, uv, just и работающий Docker. Версия Python закреплена в `.python-version`, `pyproject.toml` и Dockerfile.airflow. Все команды выполняются из корня проекта, без ручной активации окружения.

```bash
just lock
just install
just pipeline
just api
```

`just lock` обновляет lock-файл; `just install` устанавливает все группы в отдельную `.venv` из uv.lock. Системный Python не используется. `just pipeline` запускает MLflow, собирает контейнер Airflow, скачивает данные, готовит выборки и обучает baseline и выбранные RandomForest. Optuna и MLP при этом не запускаются. Контейнер Airflow удаляется после завершения, результаты остаются в runtime.

`just api` собирает Dockerfile.api и запускает контейнер в текущем терминале; остановка — Ctrl+C, после остановки контейнер удаляется. Исходники и frontend находятся внутри образа, готовые модели подключаются только для чтения, SQLite сохраняется в runtime/service на хосте. При отсутствии моделей запуск завершается ошибкой: сначала выполните пайплайн или разместите готовые артефакты в `runtime/models/classical/`. Нужны class.joblib и nsp.joblib.

- Страница: http://127.0.0.1:8001/
- Swagger: http://127.0.0.1:8001/docs
- MLflow: http://127.0.0.1:5001/
- Airflow: http://127.0.0.1:5003/ — только во время работы пайплайна.

API устанавливается в чистую среду Linux из uv.lock: только группа service, без Jupyter, PyTorch, MLflow и Airflow. API_HOST=0.0.0.0 задан в .env; порт публикуется только на 127.0.0.1 хоста.

## Конфигурация

Justfile загружает `.env` в окружение. Pydantic-settings читает окружение с префиксами, не открывает `.env` самостоятельно. В текущем файле только публичные настройки, секретов нет.

| Префикс | Назначение / пример |
|---|---|
| `PIPELINE_` | Источник, пути, seed: `PIPELINE_RANDOM_STATE=42` |
| `RANDOM_FOREST_` | Параметры baseline/CLASS/NSP: `RANDOM_FOREST_CLASS_PARAMETERS__MAX_DEPTH=12` |
| `MLFLOW_` | `MLFLOW_HOST`, `MLFLOW_PORT` |
| `EXPERIMENT_` | Бюджеты Optuna, настройки классических моделей и MLP |
| `API_` | `API_HOST=0.0.0.0`, `API_PORT=8001`, уровень логов |
| `SERVICE_` | Пути моделей, контрольного CSV и SQLite |

Двойное подчёркивание в RandomForestSettings отделяет группу параметров от поля; `None` означает отсутствие ограничения. `JUPYTER_PORT` и `AIRFLOW_PORT` задают порты инструментов в Justfile. MLFLOW_HOST по умолчанию равен 127.0.0.1 для локальных экспериментов; в Dockerfile.airflow он задан как host.docker.internal. Пути сервиса определяются настройками относительно корня проекта. Docker-публикация порта и подключение каталогов остаются в Justfile. После изменения настроек перезапустите соответствующий процесс. После изменения модели для обучения повторно запустите пайплайн.

## API и интерфейс

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка процесса |
| POST | `/predict` | Два предсказания по features, без сохранения |
| GET | `/demo/cases` | 20 контрольных примеров с измерениями и истинными метками |
| POST | `/demo/records` | Отправить case_id, предсказать и сохранить исследование |
| GET | `/records` | Список сохранённых исследований |
| GET | `/records/{record_id}` | Карточка исследования |
| DELETE | `/records/{record_id}` | Удалить запись: 204, неизвестный ID: 404 |

```bash
curl http://127.0.0.1:8001/health
curl -X POST http://127.0.0.1:8001/demo/records \
  -H 'Content-Type: application/json' -d '{"case_id":"D01"}'
curl http://127.0.0.1:8001/records
```

POST /predict принимает `{"features": {...}}` со всеми 21 полями из списка входов выше. Полный контракт и пример доступны в Swagger. Неполные данные, лишние поля, CLASS/NSP внутри features, нечисловые или бесконечные значения отклоняются с 422; неизвестный контрольный пример — 404. Ответ содержит model=RandomForest и prediction с объектами class/nsp, каждый с code и label. Для сохранённых исследований добавляются record_id, case_id, created_at и reference. Истинные ответы находятся в ответе API; переключатель скрывает их только визуально.

Таблица показывает ID, время, цветной NSP и паттерн, обновляется каждые 5 секунд. Зелёный — норма, жёлтый — подозрительный, красный — патологический. При показе истинных меток совпадения и ошибки отмечаются отдельно для обеих целей. Все измерения находятся в карточке; Tendency отображается как направление смещения. Корзины в строке и карточке удаляют запись из SQLite. Повторная отправка примера создаёт новый короткий ID.

Контрольные данные: `src/classifier/api/resources/demo_cases.csv`, два примера каждого CLASS из test. Это набор для демонстрации, не самостоятельная оценочная выборка.
